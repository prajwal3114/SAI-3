# Service Snaps

Service Snaps helps people find, compare, review, and book local service professionals.

## Stack

- Frontend: React, Vite, Tailwind CSS, React Router, Axios
- Backend: Node.js, Express, PostgreSQL (`pg`), JWT, bcrypt, Multer

## Requirements

- Node.js 22.12 or later
- A PostgreSQL database with TLS enabled

## Setup

Install dependencies from the repository root and each app folder:

```bash
npm install
npm install --prefix backend
npm install --prefix frontend
```

Create `backend/.env` with:

```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require
JWT_SECRET=replace-with-a-long-random-secret
PORT=5000
```

The backend creates the `users` and `providers` tables on startup. Use [backend/.env.example](backend/.env.example) as a template. Keep `.env` private; it is ignored by Git.

## Run both apps

From the repository root:

```bash
npm run dev
```

The frontend is at `http://localhost:5173` and the API is at `http://localhost:5000`. Vite proxies API and image requests to the backend. You can also run `npm run build` and `npm run lint` from the root.

## API

- `GET /api/health`
- `POST /api/auth/signup`
- `POST /api/auth/login`
- `GET /api/providers` (supports profession, cost, rating, availability, and sort filters)
- `GET /api/providers/seed` (creates sample providers when needed)
- `GET /api/providers/:id`
- `POST /api/providers` (authenticated; accepts up to five images)
- `POST /api/providers/:id/reviews` (authenticated)
- `POST /api/providers/:id/book` (authenticated)

## Deploy to Vercel and Render

The repository includes `frontend/vercel.json` and `render.yaml` for the split deployment. Connect this repository to both services. Set Vercel's Root Directory to `frontend`; its config installs from `frontend/package-lock.json`, builds Vite, and serves `dist`. Create the Render service from the Blueprint in `render.yaml`; it sets `backend` as the service root and uses `/api/health` for health checks.

Set these values during setup:

- **Render `DATABASE_URL`**: the PostgreSQL connection URL. Store it in Render's environment settings, not in the repository.
- **Render `CORS_ORIGINS`**: the exact Vercel origin, such as `https://your-project.vercel.app`. Add custom or preview origins as comma-separated values if needed.
- **Vercel `VITE_API_BASE_URL`**: the Render API URL ending in `/api`, such as `https://your-service.onrender.com/api`.
- **Render `JWT_SECRET`** is generated by the Blueprint.

The included Render Blueprint uses the free web-service plan. The service filesystem is temporary on that plan, so provider image uploads can disappear when the service restarts or redeploys. The generated sample image is recreated on startup. Persistent user uploads require paid persistent storage or an external object-storage service. The Vercel SPA rewrite is included so direct navigation to routes such as `/providers/:id` works after deployment.
